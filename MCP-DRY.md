# MCP + `.service`: keep it DRY — reuse `src/`, never re-port it

> **DRY is non-negotiable here.** The MCP/`.service` is a *second front-end* over
> the same library. If you re-implement the library's read/contract logic as
> hand-written `.mjs`, you now have **two copies of the truth** that silently
> drift — a query gets fixed in `src/`, the agent keeps returning stale shapes,
> and nobody notices until on-chain data looks wrong. The logic must live **once**,
> in `src/`. The MCP *consumes* it.

This is the lesson from a real review of the Celaut MCP rollout across
`source-application`, `forum-application`, and `game-of-prompts/app`: the first
pass hand-ported `src/lib/ergo/*` into a ~470–1064 line `mcp/core.mjs` (and copied
it again into `.service/`, and copied `contracts/*.es` into both). The maintainer's
note was blunt and correct — *"we don't follow DRY."* This doc is the fix, so you
don't repeat it.

See [`MCP.md`](./MCP.md) for the overall MCP + three-signer setup; **this file
overrides `MCP.md` §2 (reads): do NOT hand-port — bundle `src/` instead.**

---

## Why you can't just `import` from `dist/`

The obvious DRY move — `import { fetchThings } from '../dist/index.js'` — fails
under bare Node, which is what tempts people into re-porting. The published
SvelteKit `dist/`:

- uses **extensionless relative imports** (`import './sourceObject'`) — Node ESM
  needs `.js`;
- pulls the **Svelte entry** of dependencies (`from 'reputation-system'`, not
  `/node`);
- imports **browser-only** modules (`$app/environment`, `dompurify`, `marked`,
  Svelte stores) that have no business in a headless server;
- and `dist/index.js` re-exports `.svelte` components, so importing the index
  drags the whole UI in.

So you can't consume `dist/` as-is. **But that's not a license to duplicate.**
The answer is a tiny build step that bundles the library's *own source* into one
Node-loadable module, with the browser edges aliased away.

## The pattern (what all three MCPs now do)

```
mcp/
  _entry.mjs              # re-exports ONLY the read/contract surface from src/lib/**
  build.mjs              # esbuild: _entry.mjs -> _generated/lib.bundle.mjs
  _generated/
    lib.bundle.mjs        # COMMITTED, banner-marked. Sealed VM needs no build toolchain.
  _stubs/
    app-environment.mjs   # export const browser = false
    dompurify.mjs         # passthrough: { sanitize: (s) => s }
    marked.mjs            # passthrough (headless returns raw markdown)
  core.mjs               # THIN adapter: import the bundle, wire env, expose to tools
  lib.mjs                # makeSigner() (seed/unsigned) + describeResult()
  writes.mjs             # Node signer adapter (the one thing you CAN'T reuse — see below)
  tools.mjs              # single TOOLS + HANDLERS + REST routes registry
  server.mjs             # stdio MCP
.service/
  server-http.mjs        # imports ../mcp/tools.mjs — NO copied logic
  Dockerfile             # copies the single shared mcp/ into the image
  service.json start.sh pack_config.json package.json
```

### 1. `_entry.mjs` — point at the real source

```js
// mcp/_entry.mjs — the ONLY list of what the MCP reuses. No logic here.
export * from '../src/lib/ergo/sourceFetch';
export * from '../src/lib/ergo/sourceObject';
export * from '../src/lib/ergo/envs';
export * from '../src/lib/ergo/hashUtils';
```

### 2. `build.mjs` — bundle it Node-safe (the aliases are the whole trick)

```js
// mcp/build.mjs  ->  npm run build:mcp
import { build } from 'esbuild';

await build({
  entryPoints: ['mcp/_entry.mjs'],
  outfile: 'mcp/_generated/lib.bundle.mjs',
  bundle: true, format: 'esm', platform: 'node',
  banner: { js: '// GENERATED by `npm run build:mcp` from src/. Do not edit by hand.' },
  // Keep shared deps EXTERNAL so the MCP resolves the SAME installed package the
  // writes use (no drift) — and so you don't inline the multi-MB ErgoScript compiler.
  external: ['reputation-system', '@fleet-sdk/*'],
  alias: {
    'reputation-system': 'reputation-system/node', // Node entry, not the Svelte one
    '$app/environment': './mcp/_stubs/app-environment.mjs',
    'dompurify': './mcp/_stubs/dompurify.mjs',
    'marked': './mcp/_stubs/marked.mjs'
  },
  loader: { '.es': 'text' } // ErgoScript contracts inline as text — see §contracts
});
```

### 3. `core.mjs` — a thin adapter, not a re-implementation

```js
// mcp/core.mjs — wire env + re-export. The business logic is in the bundle (= src).
import * as lib from './_generated/lib.bundle.mjs';
const EXPLORER = process.env.APP_EXPLORER_API || 'https://api.ergoplatform.com';
export const fetchThingsByHash = (hash) => lib.fetchFileSourcesByHash(hash, EXPLORER);
// ...one line per tool. If a "tool" needs more than glue, the logic belongs in src/.
```

Result across the three repos: `core.mjs` went **470 → 84**, **~1064 → 161**, and
forum's whole hand-port collapsed to a thin adapter — all while `tools/list`
returned the **exact same tool set** (proven by diffing before/after).

## Contracts: reuse the root `.es`, don't copy them

The original GOP MCP copied `contracts/*.es` into `mcp/` *and* `.service/` — three
copies of every contract. The fix: the library's own `src/lib/ergo/contract.ts`
already compiles the root `contracts/*.es`; reuse **that**, and let esbuild inline
the `.es` sources via `loader: { '.es': 'text' }` (an esbuild plugin strips Vite's
`?raw` suffix). The copies are deleted. The contract sources now live **once**, at
the repo root, and the app and the MCP compile from the same files.

Verify it with a tool: `GET /api/contracts` must return every contract's address +
ErgoTree template hash — proof the bundle compiled them from the single root source.

---

## The one thing you legitimately can't reuse: writes

Browser write paths (`sourceStore.ts`, `commentStore.ts`, the game `actions/*`) call
the injected `ergo` wallet connector, which doesn't exist in Node. So `writes.mjs`
is a **thin Node signer adapter** over the library's underlying primitives
(`create_opinion_with_signer` / `create_profile_with_signer` from
`reputation-system/node` + `makeSigner()`), **not** a re-port of business logic.
That's necessary glue, and it's small. Multi-box / chained browser-only actions stay
browser-only and are **enumerated**, never faked.

---

## De-dup `mcp/` ↔ `.service/`

A Celaut `.service` is a sealed microVM, but "self-contained" must not mean
"committed twice." Don't copy `core/lib/writes/tools` into `.service/`. Instead:

```js
// .service/server-http.mjs
import { TOOLS, HANDLERS, ROUTES } from '../mcp/tools.mjs';
```

…and have `.service/Dockerfile` copy the single shared `mcp/` into the image. One
source of truth; the microVM stays self-contained at *build* time, not by
duplicating files in git.

---

## DRY checklist for an MCP PR

- [ ] No read/contract logic re-implemented in `.mjs` — `_entry.mjs` re-exports `src/`.
- [ ] `_generated/lib.bundle.mjs` is committed and built by `npm run build:mcp`.
- [ ] Shared deps (`reputation-system`, `@fleet-sdk/*`) kept **external** → no drift.
- [ ] `contracts/*.es` reused from root via the `.es` text loader — no copies.
- [ ] `.service/` imports `../mcp/*` — zero duplicated logic files committed.
- [ ] `tools/list` is identical before/after the refactor (no tools lost).
- [ ] The diff **removes** net lines. If a refactor for DRY *adds* lines, look again.

> If you find yourself copy-pasting a function out of `src/` into the MCP, stop.
> That copy is a future bug. Bundle the source instead.
